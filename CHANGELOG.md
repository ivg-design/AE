## [Unreleased]

### Added
- **New script — `Verticalizer` `1.9.4`** (composition): a one-click landscape-to-portrait split-screen rig builder, resolution-agnostic end to end, with an animatable picture-in-picture morph, keyframable per-card aspect easing, per-caption control panels, marker-driven subtitle tracks, a run-time-chosen rig size, and an in-place rig repair/upgrade path.
  - **A rig can now be repaired and upgraded in place instead of rebuilt from scratch (1.9.0).** Pressing **Create Portrait Rig** on a comp that already contains `[CTRL] Verticalizer` now opens a three-way dialog — **Re-apply / Upgrade Rig**, **Create New Rig**, or **Cancel** — instead of colliding with (or refusing to touch) the existing build; a headless run can set `$.global.VERTICALIZER_REPAIR = true` to choose repair without showing the dialog. The repair fixes broken expressions (a renamed layer, an expression cleared by a paste, a project round-tripped through a machine missing the pseudo effect) and upgrades a rig built by an older script version in place, both without losing work: it re-derives every expression the rig owns on **rig layers only** (a fixed name inventory plus every `Caption NN ...` set and the three TOP/BOT/BG source instances — anything else in the comp is left alone), adds whatever structural pieces the current version expects and an older rig lacks (matte/card PiP holes, the `PiP Shadow` pair, `PIP Handle`, the `Z TOP`/`Z BOT` nulls) using the same builders a fresh build uses, and upgrades a stale pseudo-effect instance (the main controller and every per-caption instance) to the current one with full value **and keyframe** migration by control display name — times, values, and interpolation preserved, hold stays hold, including the `PiP Amount` → `PiP Transition` rename. Keyframes survive by construction rather than by care: wiring only ever assigns expressions, the few static writes go through a helper that refuses a keyframed property, and a PAN handle whose Position is already keyframed is left un-reparented rather than rewritten. Any control the new panel has no equivalent for, or a handle left un-reparented for that reason, is **named** in the completion report instead of being guessed at or silently dropped. Internally, the wiring that used to live only inside the builder functions was pulled out into one `wire*` function per layer type, and both a fresh build and a repair now call the same functions, so a repaired rig can't drift from a freshly built one. Repair runs in its own undo group with automatic rollback on failure, same as a fresh build.
  - Builds a `<name> Portrait` master comp (1080×1920 by default, or any size chosen from the panel's **Rig Size** section) plus a native-resolution `SRC <name>` precomp, wiring the same source into two independently framed picture-in-picture windows via per-layer track mattes rather than masks, so the crop stays fixed in comp space as each window pans and zooms. No expression bakes any comp dimension — every one derives from `thisComp.width` / `thisComp.height` at runtime, so the rig survives a comp-settings resize and works at any comp size.
  - **Duik-style locked-path handles** — `SPLIT Handle`, `TOP PAN Handle`, `BOT PAN Handle`, `PIP Handle`, `CAPTION Handle`, and a `Caption NN Handle` per caption added afterward (all free on **both** X and Y) — own everything spatial and keyframable (split line Y — full comp travel, so sliding the handle to an edge hides that pane entirely, per-window pan/rotation, floating-card centre, each caption's own band position); every handle glyph's Path carries a `"value"` expression so a drag always moves the layer, never reshapes the glyph. `PIP Handle` hides itself while `PiP Transition` is 0, and every caption handle hides itself while its own `Show Captions` is off — `Show Handles` still wins over both.
  - Everything numeric and stylistic for the rig lives on one embedded **`Verticalizer` pseudo effect** (match name `Pseudo/IVGD Verticalizer9`, 78,432 bytes, **69 controls across 9 top-level groups** — `Interface`, `Layout`, `PiP`, `Top Card`, `Bottom Card`, `Divider`, `Background`, `Captions`, `Safe Zones`), with `Top Card` / `Bottom Card` each nesting four mirrored sub-groups — `Framing` (Aspect, **Aspect Ease**, Inset, **Scale Mode**, Zoom, Clamp Pan), `Style` (Corner Radius, Edge Feather, Opacity), `Border & Shadow` (Border Width/Color, Shadow Opacity/Softness/Distance/Angle), and `Time` (Speed %, Time Offset in frames, plus a read-only Source Frames readout) — so every card-scoped control is fully independent per side instead of shared, and rounding or bordering one window can never force the other to match. `Layout` carries Gap, a `Seam Mode` popup (Gap / Inset) and `Seam Inset %` slider, and an exclusive Audio Source popup (top/bottom/muted, via each window's Audio Levels; the background instance is always silent); `Aspect` (Cover / 1:1 / 16:9 / 9:16 / Fit Height / Fit Width, using the source's own aspect for the two Fit modes) and Inset resolve each window's box independently; a Captions▸Box Stroke Width/Color outline sits independent of the fill's own Box Opacity — registered without an external `.ffx` file via the CamBot temp-comp registration trick.
  - **Keyable Aspect: hold-keyframing a card's shape now morphs instead of cutting (1.8.0).** Every card gains an `Aspect Ease` slider (frames, 0–120, default 15) directly under its `Aspect` popup. For that many frames after an Aspect keyframe, the window geometry — the split-mode fit and the PiP floating box's aspect ratio alike — eases linearly from the previous keyframe's aspect to the new one's instead of jumping on the keyframe's exact frame: keyframe `PiP Transition` to glide 0→100 over a range, drop a hold key on the card's `Aspect` somewhere inside that range, give it an Ease, and the pane reshapes smoothly mid-flight instead of snapping. Split, Seam Mode, Inset, and `PiP Transition` all keep animating live underneath the blend. Ease `0`, or a card whose Aspect carries no keyframes, reproduces the pre-1.8.0 instant-cut behavior to the pixel. This is what bumps the match name to `Verticalizer9` above, and the registration probe now asks for `Top Aspect Ease`; the standalone `Verticalizer Caption` effect is untouched.
  - **PiP no longer exposes the background card's own fill (1.7.4).** The PiP occlusion trick's Window/Hole/Merge Paths (Subtract) lived only on each matte, so it only ever cut the *video* out of the background card's window — the background card's own filled border rect underneath was untouched and showed straight through the floating card's hole as a flat solid block instead of the floating card's video. Both cards' shape groups now carry the identical hole subtract their mattes already carry (the same three hole expressions, reused verbatim), live only on whichever card is currently the background card. Field-diagnosing it also confirmed the one remaining unknown in the Merge Paths math: After Effects evaluates a Subtract operator as Window minus Hole, not the reverse.
  - **SPLIT handle now travels the full comp height (1.7.3).** The split clamp used to keep the line `CH/12` from either edge and gave every window box an 8 px floor, so a pane could never shrink past a sliver. Both guards are gone — the split rubber-bands across the full `0..CH`, a collapsed pane's window reaches exactly zero, and each card's border/shadow now also gates on window size so no border dot survives at the edge. Drag the handle to the bottom to show only the top pane, or to the top for only the bottom pane.
  - **Per-caption control panels via a second embedded pseudo effect.** Every caption used to share the controller's single `Captions` group and single `CAPTION Handle`, so a second caption could not be resized, recoloured, or switched off without moving the first one with it. **`Add Caption`** now builds a complete, independent caption: its own `Caption NN Handle` carrying its own instance of a new pseudo effect, **`Verticalizer Caption`** (match name `Pseudo/IVGD VerticalizerCap2`, 11,866 bytes, **13 controls** — Show Captions, Caption Source, Caption Fade, Fade Frames, Captions Size, Caption Max Width, Text Color, Box Color/Opacity/Stroke Width/Stroke Color/Padding X/Padding Y, mirroring the controller's `Captions` group exactly), plus its own text and box wired to that instance. Only the expression *prelude* differs between the first caption and an added one (which effect `FX` — and, in Markers mode, which marker source `MKSRC` — binds to); every expression *body* is written once and shared, so the two paths can never drift apart — `Add Caption` duplicates the first caption's layers and explicitly repoints every one of the duplicated expressions at the new handle.
  - **Marker-driven captions and matching fades (1.7.0).** Both caption systems gain `Caption Source` (Manual | Markers), `Caption Fade` (checkbox), and an integer `Fade Frames` (0–120, typeable to 999), inserted right after `Show Captions`. In Markers mode the caption becomes a subtitle track: the text becomes the active marker's comment for exactly `[marker.time, marker.time + marker.duration)` and nothing between markers (half-open segments; overlapping/adjacent markers resolve to the last one starting at or before now). Markers live on the caption's own **text layer** (the layer you already select to type into), with the **comp's** marker row as the automatic fallback when the text layer has none — so any number of parallel subtitle tracks can coexist without colliding, and a plain ruler-level track drives the built-in caption with zero setup. Zero-duration markers show nothing — duration is what makes a marker a caption — and with fades on, a marker shorter than fade-in + fade-out throws a descriptive expression error naming the insufficient duration (1.7.2 field corrections). `Caption Fade` fades the text and its box together (outline included) via a single layer-opacity multiply, never on the box's own fill opacity: in Markers mode the fade lives strictly inside the marker segment (the first/last `Fade Frames`, with short segments capping their peak instead of overshooting); in Manual mode it runs against the text layer's own in/out points. With `Caption Fade` off the rig is bit-for-bit what 1.6.1 produced. Because both effects gained controls, both match names bump — `Verticalizer7` → `Verticalizer8`, `VerticalizerCap1` → `VerticalizerCap2` — and both registration probes now ask for `Caption Source`, a name that exists only in these binaries.
  - **Rig Size, chosen at run time.** The rig was always resolution-agnostic at runtime, but `Create Portrait Rig` was hard-wired to build at 1080×1920. The panel now carries a **Rig Size** section — presets for HD / 2K / 4K Portrait, Feed 4:5, Square, 720 Portrait, plus two typeable W/H fields (typing switches the dropdown to Custom; both are clamped to AE's own 4–30,000 px limits) — and a headless run can set `$.global.VERTICALIZER_WIDTH` / `VERTICALIZER_HEIGHT` instead. Before building, the source is checked against the rig and a dialog offers to proceed or go back if the footage would need real upscaling to fill its window (see the source-coverage fix below); answering "go back" creates nothing.
  - **Versioned rig names.** Re-running `Create Portrait Rig` on a source that already has a `Verticalizer/<name>/` folder used to file a second, identically-named folder and comp with no way to tell the two builds apart. The base name is now version-stamped *before* anything is created (`<name>`, then `<name> v2`, `v3`, …, checked project-wide so a deleted folder or relocated comp still counts as taken), and every derived name (job folder, `SRC <name>`, `<name> Portrait`, the `TOP` / `BOT` / `BG` footage layers) is built from that one stamped base.
  - **Per-card Scale Mode (1.4.0) decouples footage scale from the window.** New `Top Scale Mode` / `Bottom Scale Mode` popups (`Fill Window` | `Fixed`, in each card's Framing group directly above Zoom) decide what Zoom is a percentage of. `Fill Window` is the original baseline — `max(winW / sw, winH / sh)` — so dragging the SPLIT handle, Gap, Seam Mode, Seam Inset %, Inset, or Aspect re-fits and re-punches the footage on every change, which breathes a finished framing in and out. `Fixed` takes the baseline from the comp instead (`max(CW / sw, CH / sh)`), which no window control can move, so dragging the split only re-crops the matte and Zoom = 100% covers the whole comp; the scale expression and the pan clamp share one builder (`eSourceScale`) so the clamp always agrees with the drawn size, and a Zoom below the window's own fill percentage in Fixed mode centres the footage and shows matte void at the edges rather than special-casing it.
  - **PiP mode (1.5.0): an animatable picture-in-picture morph.** A new `PiP` group adds `PiP Panel` (Top | Bottom — which window floats), `PiP Transition` (0–100%, **keyframeable** — renamed from `PiP Amount` in 1.6.0) and `PiP Scale` (the floating window's width as a percentage of comp width), plus a new draggable orange `PIP Handle` that the floating window centres itself on. The per-section window resolver now derives the split box first and a PiP target second, then lerps every window quantity between them at `t = PiP Transition / 100` — the floating card's target is "comp width × PiP Scale% wide by its own Aspect, centred on the PIP Handle," the background card's is "the comp shrunk by its own Inset on all four sides." Because it's a lerp and not a mode switch, `t = 0` reproduces the pre-1.5.0 split geometry bit for bit, and because matte, card, footage scale/position, pan clamp and the `Z TOP`/`Z BOT` nulls all re-derive the same resolver, everything morphs together for free once `PiP Transition` is keyframed. Occlusion is solved without restacking layers: each matte gained a second "Hole" rect and a Merge Paths (Subtract) — zero on the floating card's own matte, and on the background card's matte exactly the other card's lerped window inflated by its Border Width and rounded by its Corner Radius + Border Width — so the background window is cut away precisely where the floating card draws, whichever side floats. The Divider's opacity is multiplied by `(1 - t)` so the split line fades out as the PiP engages.
  - **PiP shadow the floating card can actually cast (1.6.0), fixing a 1.5.0 known caveat.** A card can't escape its own place in the layer stack, so with `PiP Panel` = Bottom the floating card's own drop shadow used to be drawn under the background card's full-comp window and was never seen. A new `PiP Shadow` layer (an `ADBE Drop Shadow` with Shadow Only ON) sits above **both** card assemblies, sized to whichever card `PiP Panel` nominates, alpha-matted by a new `PiP Shadow Matte` layer (the whole comp minus that card's rect, built from the same Merge Paths/Subtract pair the window mattes use) so the soft edge can't spill back over the card casting it. Both layers' opacity is `PiP Transition`; the floating card's own shadow cross-fades out by `(1 - t)` over the same interval so the two are never drawn at once. Either `PiP Panel` choice now casts a real shadow.
  - **Handle transform locks (1.5.0).** Every handle plus `[CTRL] Verticalizer` now carries a static `"[100,100]"` Scale expression, and `SPLIT` / `CAPTION` / `PIP` / `[CTRL]` a static `"0"` Rotation expression, so a stray corner-drag or rotate gesture in the viewer can no longer distort a handle or silently change what the rig reads; `TOP PAN Handle` / `BOT PAN Handle` deliberately keep a free Rotation, because that **is** the per-window footage rotation input. Each handle's inner `Glyph` group is pinned the same way (Rotation `0`, Position `[0,0]`).
  - **Seam Mode fixes the seam-doubling bug and gives it two behaviors.** Inset now shrinks only a card's comp-facing edges; the seam edge is owned separately by `Seam Mode`: `Gap` holds the two windows exactly `Gap` pixels apart no matter what either Inset is (previously the seam silently read `Top Inset + Gap + Bottom Inset`, so insetting a card to frame it off the comp edge blew the middle spacing open, and winding Gap negative was the only workaround); `Inset` instead pins each card's seam edge at that card's own Inset × `Seam Inset %` from the split line and ignores Gap — 50% means the two half-insets add up to one full inset of seam, e.g. two 30 px insets land a 30 px seam matching the 30 px outer framing. The window box is asymmetric as a result, so the window centre used by mattes, footage, cards, and the `Z TOP`/`Z BOT` pan-null anchors is the centre of that box, not the section.
  - **Per-card time remapping, integrated frame-by-frame.** Each window's Time Remap carries an expression reading that side's Speed (0–400%, 0 = freeze frame) off the controller and integrating it — every frame from the layer's in point contributes `Speed × frameDuration` — so keyframing Speed `100 → 0 → 100` freezes on a held frame and resumes from that same frame instead of jumping (the previous formula re-derived position from the current speed and the whole elapsed time, so restoring speed after a freeze snapped the clip forward). The integral loop only runs while Speed actually carries keyframes; a static Speed still takes the closed-form fast path, so there's no per-frame cost unless a ramp is in play. `Time Offset` is in **frames** and adds to the integrated position — keyframing it while Speed is 0 is the manual, frame-accurate scrub workflow — and a read-only `Source Frames` slider bakes the source's length in frames as a numeric-literal expression, so the legal Time Offset range is visible in the same panel.
  - **Safe zones rebuilt in absolute comp space.** The `Safe Zones` layer is pinned at anchor/position `[0,0]` with no transform expression at all, and every band (plus the safe-rect outline) carries expressions on both its Size and its Position in absolute comp coordinates, fixing a misplaced/undersized overlay for good — verified across 3 comp sizes × 4 platforms in simulation.
  - **Lock + shy hygiene.** Every structural layer (mattes, footage, cards, `PiP Shadow` / `PiP Shadow Matte`, divider, background stack, each caption's box, safe zones, both Z nulls — 16 layers) is shied and locked at the end of the build and the master comp opens with Hide Shy Layers on, so the timeline shows only 7 layers (`[CTRL] Verticalizer`, the handles, `Caption Text`) out of 23 instead of the full 21-layer stack pre-1.5.1; **Add Caption** keeps each new caption's text layer unlocked while its box joins the locked stack, and (as of 1.6.1) the new text/box/handle span the full comp duration rather than a 3-second clip from the current time indicator.
  - Match name bumped four times more since 1.4.0 — `...Verticalizer6` (1.5.0, PiP group/Scale Mode/handle locks), `...Verticalizer7` (1.6.0, the `PiP Amount` → `PiP Transition` rename), `...Verticalizer8` (1.7.0, the `Caption Source` / `Caption Fade` / `Fade Frames` additions), then `Pseudo/IVGD Verticalizer9` (1.8.0, the `Top Aspect Ease` / `Bottom Aspect Ease` additions) — because AE registers one pseudo-effect definition per match name per session (first loaded wins), so a changed control set always ships under a fresh identity rather than reusing a shipped one (`...Verticalizer5` at 61 controls for 1.4.0, `...Verticalizer4` at 59 controls for 1.3.0, and so on back to the original 29-control `...Verticalizer`); the effect display name stays `Verticalizer`, keeping every expression intact. The registration probe now asks for `Top Aspect Ease`, a name that exists only in the current binary; the standalone `Verticalizer Caption` effect is untouched by this bump and stays `Pseudo/IVGD VerticalizerCap2`, probed on `Caption Source`.
  - Dockable three-button panel (**Create Portrait Rig** / **Add Caption** / **Apply Rig FFX**) with automatic rollback on failure (the partial build is undone), automatic legacy→JavaScript expression-engine switching, and headless test hooks (`$.global.VERTICALIZER_AUTORUN` / `VERTICALIZER_SILENT` / `VERTICALIZER_LOG`, plus `VERTICALIZER_WIDTH` / `VERTICALIZER_HEIGHT` since 1.6.0). Run as a floating window, it now closes itself after a successful action so it doesn't sit on top of the rig it just built; docked as a panel it has no API to close itself and stays put. A run that fails or has to warn leaves the window open either way, so the buttons are still reachable.
  - **`1.6.1` field fixes.** (1) The source-coverage warning measured comp cover, so an ordinary 1920×1080 source warned "178%" on a plain 1080×1920 rig even though its actual split *window* only needed ~87%; it now measures the default split window (comp width × half comp height) and warns only above a genuine 110% upscale, and the separate "source is too large" warning is gone entirely (extra resolution is just punch-in headroom). (2) Pseudo-effect registration wrote its temp `.ffx` to `Folder.temp`, which on recent macOS resolves inside the OS-managed `.../T/TemporaryItems` and could be emptied before After Effects read the preset back, failing with `"File not found (3 :: 0)"`; it now writes to a stable `IVGD` folder under `Folder.userData` (falling back to `Folder.temp` then `Folder.desktop`), trusting the write only once the file is verified to exist. (3) A caption handle's visibility expression addressed the caption effect by a control name instead of the effect name, which silently errored in AE and left the handle visible regardless of its own `Show Captions` — fixed to go through the effect name. (4) `Add Caption` no longer trims a new caption to the current time indicator + 3 seconds; its text, box, and handle now span the full comp duration, leaving trimming entirely to the editor.

### Changed
- **Pseudo-effect match-name collision fixed across six scripts.** After Effects registers exactly **one pseudo-effect definition per match name per session** — whichever definition loads first wins, and every later effect claiming that same match name is re-interpreted through it. Five catalog scripts shipped Pseudo Effect Maker's untouched default `Pseudo/PEM Matchname`, and `Elast-o-matic` shipped PEM's generic auto-generated ids, so using any two of them together in one session silently corrupted each other's control panels: applied rigs reset with *"effect control conversion required"*, sliders came back with the wrong names/ranges, and the driving expressions lost their parameters. Each script's pseudo effect now carries a unique `Pseudo/IVGD …` match name (rewritten in the embedded FFX binary's `tdmn` chunks and PEM JSON metadata — the RIFX payload is otherwise byte-for-byte unchanged, so control names, defaults, ranges and ids are untouched). Projects **already saved** with the old match name keep working, because their effect definition is embedded in the project file; only newly-applied rigs take on the new identity.
  - `Rectangulator` `2.1.6` → `2.1.7` — "Rectangulator Controls": `Pseudo/PEM Matchname` → `Pseudo/IVGD Rectangulator`.
  - `BurstMate` `2.0.1` → `2.0.2` — "Void": `Pseudo/PEM Matchname` → `Pseudo/IVGD BurstMateVoid`. (The "Stroke Burst" preset already had its own `Pseudo/stroke_burst` and is unchanged.)
  - `SubtitleForge` `2.0.1` → `2.0.2` — "Subtitle Setup": `Pseudo/PEM Matchname` → `Pseudo/IVGD SubtitleForge`.
  - `Parent-o-bot` `2.0.2` → `2.0.3` — "Multi_Parent": `Pseudo/PEM Matchname` → `Pseudo/IVGD ParentOBot`.
  - `Distributron` `1.1.2` → `1.1.3` — "Distribute Along the Path": `Pseudo/PEM Matchname` → `Pseudo/IVGD Distributron`. The dev template `tools/templates/expression-controls/DistributeAlongPath.ffx` was patched to match, so a future re-embed can't regress.
  - `Elast-o-matic` `1.1.2` → `1.1.3` — "Inertial Bounce": `Pseudo/595056` → `Pseudo/IVGD ElastOMaticIB`; "Bounce": `Pseudo/477756` → `Pseudo/IVGD ElastOMaticB`. This script resolves its controller **by match name** (`canAddProperty` / `addProperty`), so the in-code match-name constants were updated alongside the binaries.
  - Field fixes from live testing (1.9.1–1.9.4): the repair prompt now also fires from the normal build workflow — selecting the **source** and pressing the button on a source that already has a rig offers the repair instead of silently building `<name> v2`; the aspect blend inherits the easing on the `PiP Transition` keyframes rather than running on linear time, so a reshape dropped inside an eased transition follows that curve; and shape-group ordering is now enforced by re-fetching each item immediately before moving it, since moving a property invalidates the sibling references taken before it — the earlier index-arithmetic and cached-reference versions could leave a card or matte group rotated, which showed up as a lost border ring or an empty matte.

## [2026-07-12]

### Added
- **New script — `CamBot` `3.15.1`** (animation): a fully-rigged 3D camera driven entirely from one effect panel.
  - Creates a camera plus a `CamBot N Target` control-host shape; every camera channel (position, orientation, roll, zoom, focus, aperture, blur) is expression-driven, so you animate controls, never the camera.
  - **One-node ↔ two-node dial** (`Look-At-Influence`): 0 = genuine free/FPS camera, 100 = locked two-node tracking — a smooth crossfade with no mode switch, because all rotation channels are rig-owned (orientation-driven aim; X/Y rotation locked, Z = roll).
  - **Multi-target blending** via duplicable `CamBot Target` controllers — aim at the weighted average of several layers and animate their influence to hand off between subjects.
  - **Moves engine** — 26 procedural camera moves (push, dolly-zoom, orbit, spiral, helix, fly-by/through, swoop, reveal, establish, whip pan, parallax, drift…) performed by keyframing one `Progress` slider, plus **Move Shaping** controls (Radius/Depth/Height/Turns/Spin, in absolute units, auto-filled per move) to resize them.
  - Focal length in millimetres, smart auto-focus depth of field, handheld shake, follow smoothing, `Realistic Limits` clamp.
- Website: CamBot doc (`docs/scripts/CamBot.md`), curated card copy, and web icon; bundle rebuild now sources icons from the committed slug-named SVG set (`site/download/native/icons/`) so `build-bundle.mjs` no longer requires the private `native/` repo.
